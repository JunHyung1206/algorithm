# 바이러스 파이프

- 출처: 프로그래머스 (문제 제목은 확인 필요)
- 유형: 구현 (완전탐색 + BFS)

## 핵심 제약

- n ≤ 100, k ≤ 10, 파이프 종류 3개
- 같은 종류를 연달아 여는 건 의미가 없으므로 순서는 3 × 2^(k-1) = 1,536개 이하이고, 순서 하나를 시뮬레이션하는 비용이 작아서 전부 시도해도 충분하다

## 막힌 점 / 배운 점

- 핵심은 "파이프 한 종류를 연다"를 코드로 옮기는 것이었다. 현재 감염된 **모든** 노드에서 출발해서 그 종류의 파이프로만 끝까지 번진다. 시작점은 1개가 아니다.
- 순서를 만들 때 "직전에 쓴 종류"와 "아직 아무것도 안 씀"을 같은 값(1)으로 표현해서, 1로 시작하는 순서가 통째로 빠졌다. 예제는 통과했지만 기준 구현과 무작위 3000개를 비교하니 621개가 달랐다. 예제 통과는 정확성의 증거가 아니다.
- 리팩터링은 이전 버전과 결과가 같은지 확인하며 한 번에 한 종류만 바꿨다. 단계는 `git log`로 볼 수 있다.

## 개선 과정

| 단계 | 바꾼 것 | n=100, k=10 평균 시간 |
|---|---|---|
| v0 | 시작값 수정 | 약 145ms |
| v1 | 이름·구조 정리 | 약 70ms |
| v2 | 인접 행렬 → 인접 리스트 | 약 9ms |
| v3 | 순서마다 처음부터 → 단계별로 상태 이어가기 | 약 2.4ms |

시간은 한 컴퓨터에서 입력 하나로 잰 대략적인 값이다. v0→v1의 차이는 같은 알고리즘이라 측정 오차일 가능성이 크고, v3은 모두 감염되면 멈추는 조기 종료의 도움도 받았다.
v3은 "순서 만들기"와 "감염시키기"가 한 재귀 안에서 만나는 대가가 있어서, 읽기 쉬운 쪽은 v2일 수 있다.
